\begin{abstract}
This work studies agents for the Kaggle \emph{PTCG AI Battle Challenge}, a rated ladder of Pok\'emon Trading Card Game programs. A first agent, \emph{DualCross}, imitates top-rated players with a transformer refined by reinforcement learning; it matches 63\% of expert decisions but rates only 650. A second agent, \emph{PTCGNet}, uses a smaller network to guide a Monte Carlo tree search on the game simulator. Search raises the fraction of games won against six fixed opponents from 0.75 to 0.90 and the rating to $\approx$770. Predicting the opponent's hand beats card counting but does not help the search.
\end{abstract}

\section{Introduction}
In the Pok\'emon Trading Card Game (PTCG) two players with 60-card decks use Pok\'emon, energy and trainer cards to knock out the opponent's Pok\'emon; six knock-outs win. On Kaggle, agents play rated best-of-three matches; at each decision an agent sees its own view of the game and a list of legal options (play a card, attach energy, attack, choose $k$ of $n$ cards, \dots) and returns the chosen ones.

The task combines \emph{hidden information} (the opponent's hand and both deck orders), \emph{stochasticity} (shuffled decks, random card effects) and a \emph{variable action space}: the options change at every decision, ruling out a fixed output layer. Kaggle gives 5k replays of top games and a simulator that implements every card effect and can continue a game from any state once the hidden cards are fixed; agents get 2 CPU cores and 600\,s per game.

Two agents, named after their networks, were built in turn: \emph{DualCross} (\S\ref{sec:gen1}) learns from replays; \emph{PTCGNet} (\S\ref{sec:gen2}) plans with the simulator. Code: \url{https://github.com/AntoCordeiro/ptcg-agent}.

\section{Related work}\label{sec:related}
Both agents feed the game as tokens to a transformer \cite{vaswani2017attention}, as AlphaStar does for StarCraft \cite{vinyals2019grandmaster}. DualCross uses behavioural cloning (BC), i.e.\ supervised learning on expert decisions \cite{pomerleau1991efficient}, offline RL with IQL \cite{kostrikov2022offline}, online RL with PPO \cite{schulman2017proximal} and weight averaging (WiSE-FT) \cite{wortsman2022robust}. PTCGNet follows AlphaZero, where a network gives priors and values to a PUCT tree search \cite{silver2016mastering,silver2018general}, expert iteration \cite{anthony2017thinking}, and determinization, i.e.\ searching on sampled hidden cards \cite{long2010understanding,cowling2012information}. Appendix~A describes these methods.

\section{DualCross: imitation and reinforcement learning}\label{sec:gen1}
The training set holds the 75k decisions of the $\approx$650 best-rated replays: observations paired with the option chosen by the player (the expert). A transformer ($d{=}256$) represents each card in play or in hand as a token of 332 hand-crafted features (Appendix~B) and each legal option as another token. A cross-attention decoder lets every option token attend to the card tokens, so an option such as ``attach energy to this Pok\'emon'' gathers information about the cards it involves; one score is output per option. BC trained it to score the expert's option highest (63.3\% top-1 on held-out decisions). IQL then imitated more strongly the decisions with higher estimated advantage (63.4\%), PPO continued by self-play against earlier checkpoints, and WiSE-FT averaged the weights of these models. At play time the agent took the top-scored option after a few one-step simulator checks (Appendix~B), using under 1\% of the time budget.

Versions were compared in 20--40 games against each other, which did not predict the ladder: the best local version rated 500, an earlier one 650. Samples this small are noisy, and own checkpoints are unrepresentative opponents; PTCGNet fixes both and uses the idle time to plan.

\section{PTCGNet: network-guided search}\label{sec:gen2}
\paragraph*{Network.} PTCGNet drops hand-crafted features: a card token sums a learned card-identity embedding, the card's static attributes from the simulator database and a few dynamic values (zone, owner, HP, damage, energy). An option token encodes the option type plus the embeddings of the card it acts on and of its target, so each option contains the cards it involves before any attention (Appendix~B). The unordered set of tokens enters a 4-layer pre-norm transformer encoder ($d{=}192$). Four heads follow: \emph{policy} (a score per option), \emph{value} (win probability), \emph{count} (how many cards to take when a decision allows $k_{\min}$ to $k_{\max}$) and \emph{belief} (the opponent's hand). Replays store both players' views, so the opponent's true hand is a training label only; the input is always the acting player's view.

The policy was trained on 453k decisions from the 3{,}000 highest-rated replays, split 90/5/5 by game, so that validation and test decisions ($\approx$20k each) come from unseen games. Trained on replays, the value head memorised the 2.7k training outcomes and did worse than a constant, so, as in AlphaGo, it was fine-tuned on 8k games of the network against itself, keeping the replay policy loss.

\paragraph*{Search.} At each decision with two or more options the agent samples a \emph{world}, an assignment of all hidden cards consistent with its view: its unseen cards are shuffled into deck and prizes; the opponent's decklist is the one, among 120 mined from replays, that best matches the visible cards; the opponent's hand is drawn from the rest, uniformly or weighted by the belief head. On this world the simulator runs a tree search over both players' moves, the opponent being modelled by the same network. Each simulation descends the tree by the PUCT rule, favouring options with high prior and value, and scores the new position with the value head rather than playing to the end, which would cost hundreds of steps for one noisy outcome. When the decision's time share ends (Appendix~D), the most visited, i.e.\ best evaluated, option is played; $k$-of-$n$ choices use the policy and count heads. Expert iteration retrains the policy on the visit distributions of search self-play.

\paragraph*{Evaluation protocol.}\label{sec:eval}
Playing strength is measured by the \emph{score}, the fraction of games won. The main benchmark, the \emph{gauntlet}, is a fixed pool of six opponents: the two DualCross submissions (ladder 650 and 500) and the raw PTCGNet policy piloting four popular decks (Dragapult, Ogerpon, Clefairy, Kangaskhan/Crustle). All runs use 200--400 games with alternating first player and the 600\,s limit, and report 95\% Wilson intervals \cite{wilson1927probable} and the Elo difference $400\log_{10}(s/(1-s))$; a sequential test (SPRT) \cite{wald1945sequential} stops when a difference is significant. Offline metrics are top-1 agreement with the expert (policy), Brier score, the squared error of the win probability \cite{brier1950verification} (value), and AUROC against the true hand (belief). The ladder rating is Kaggle's TrueSkill-like skill estimate $\mu$ \cite{herbrich2006trueskill}, starting at 600.

\paragraph*{Network.} The policy agrees with the expert on 70.0\% of test decisions (21.7\% at random). Self-play makes the value beat a constant (Brier .254 $\to$ .226 vs .249). The belief reaches AUROC .752, vs .711 for counting the opponent's unseen cards. Piloted by the policy against the gauntlet, Kangaskhan/Crustle scored .73 and Dragapult, the most common top deck, .49 (Appendix~C): the deck must suit the agent, so Crustle was used.

\paragraph*{Search.} Search is the main source of strength (Fig.~\ref{fig:scaling}, Appendix~C): the gauntlet score goes from .75 (policy) to .87 (256 simulations) and .90 (deployed agent), which beats its own policy .59 (+65 Elo): a weak value head suffices.

\paragraph*{Hidden information.} Search depth matters more than accurate hidden cards: sampling the hand from the belief head does not change the score (.48, 400 games), and four worlds with a quarter of the simulations each lose to one deeper search (.39, $-75$ Elo), as on the ladder (737 vs 768).

\paragraph*{Expert iteration and time.} Expert iteration with 64-simulation targets (16 did not help) improved the search agent (.57, +49 Elo, 300 games) but not the raw policy (.50): it learned priors for search, not imitation. A further round, and doubling the time cap from 3 to 6\,s, gave no gain (.50; .49 [.43,.56]).

\section{Discussion and conclusions}
Better imitation and RL did not make a stronger player; a smaller network guiding search did (650 $\to$ $\approx$770). As neither belief, more expert iteration nor more time helps, the network and opponent model are now the limit. The gauntlet, mostly built on the agent's own network, saturates near .90, while 800-rated ladder opponents win half the time: stronger test opponents come next.

\section*{Appendix A: methods}\label{app:methods}
\paragraph*{Behavioural cloning (BC).} Supervised learning of a policy $\pi(a\mid s)$ by minimising the cross-entropy between the predicted distribution over legal options and the option chosen in the replay.
\paragraph*{Implicit Q-learning (IQL).} An offline RL method that fits a state value $V(s)$ and an action value $Q(s,a)$ from the recorded games only, and then trains the policy by advantage-weighted regression: the imitation loss of each recorded action is multiplied by $\exp(\beta(Q(s,a)-V(s)))$, so actions that led to better outcomes than expected are imitated more strongly.
\paragraph*{PPO.} An online policy-gradient method: the agent plays games, estimates the advantage of each action (here with generalised advantage estimation), and updates the policy with a clipped objective that prevents large changes per update. Opponents were sampled from a league of earlier checkpoints, and a BC term kept the policy close to expert play.
\paragraph*{WiSE-FT.} The weights of a fine-tuned model and of the model it started from are averaged, $\theta=(1-\alpha)\theta_0+\alpha\theta_1$; when the two are close in weight space the average often generalises better than either. Here the BC, IQL and PPO models were averaged.
\paragraph*{PUCT search.} Each tree node stores, for each option $a$, a prior $P(a)$ from the policy head, a visit count $N(a)$ and a mean value $Q(a)$. A simulation selects at each node $\arg\max_a Q(a)+c\,P(a)\sqrt{\sum_b N(b)}/(1+N(a))$ ($c{=}1.25$), expands the first new position, evaluates it with the value head, and adds the value to every node on the path, with the sign flipped at the opponent's nodes. Forced moves and $k$-of-$n$ selections inside the tree are played by the policy, so the depth is spent on real choices.
\paragraph*{Expert iteration (ExIt).} The search acts as an expert that improves on the network; the network is trained to reproduce the search's visit distribution (and the game outcome for the value), and the improved network is used in the next round of search.

\section*{Appendix B: inputs of the networks}\label{app:features}\label{app:gen1}
\paragraph*{DualCross.} Up to 60 state tokens and 80 option tokens of 332 hand-crafted features each: card statistics, rule flags, damage formulas written by hand for 12 attacks, frozen 384-d text embeddings of the card descriptions, and the output of a hand-written card tracker. At play time the simulator was used only to play an immediately winning attack, to avoid emptying the agent's own deck, and, when the two best options were within 0.15 in probability, to simulate both one step and keep the one the value head preferred. Eight symbolic relations per (option, card) pair (e.g.\ ``this option evolves this card'') were added as attention biases in the cross-attention decoder, and a pointer decoder selected cards one at a time in $k$-of-$n$ decisions.
\paragraph*{PTCGNet.} \emph{Card tokens} ($\leq$64): every Pok\'emon in play, the cards in the agent's hand, the stadium, cards revealed by an effect, and any card an option refers to; 38 features (zone, owner, HP, damage, attached energy by type, tools, evolution stage, status conditions, bench position) plus the card-identity embedding and a projection of the card's static attributes (type, HP, weakness, resistance, retreat cost, attack costs and damage). \emph{Option tokens} ($\leq$80): 35 features (17 option types such as play, attach, evolve, attack, retreat, end turn; counts; energy type) plus embeddings of the card it acts on, its target, and the attack if any. \emph{Global token}: turn, per-player deck/hand/prize/bench/discard sizes, flags for actions already taken this turn, and the type of selection requested. \emph{Discard tokens}: the mean embedding of each player's discard pile. The same encoding function is used in training, in search and in the submitted agent.

\section*{Appendix D: training and compute}\label{app:train}
\paragraph*{Training.} Supervised training: AdamW (lr $4\cdot10^{-4}$, weight decay 0.05, batch 512, 12 epochs; loss weights policy 1, value 0.25, count 0.2, belief 0.05; decisions of the losing player weighted 0.5), $\approx$45 min on one RTX 4070 Ti SUPER; the checkpoint is selected on the validation split and the test split is used only for the reported metrics. Value fine-tuning and ExIt: 3 epochs, lr $1.5\cdot10^{-4}$, on 8k self-play games of the policy (value) and on 2{,}400 self-play games with 16 simulations (ExIt-1) and 1{,}600 with 64 simulations (ExIt-2).
\paragraph*{Time management.} The time for a decision is $\max(0.05,\min(t_{\max},(T-r)/d))$ seconds, where $T$ is the remaining time bank of the game, $r$ a reserve and $d$ a divisor; the deployed agent uses $t_{\max}{=}3$\,s, $r{=}60$\,s, $d{=}60$, averages $\approx$2.4\,s per searched decision and uses about 185\,s of the 600\,s bank per game.
\paragraph*{Evaluation.} 20 games run in parallel on a 24-thread CPU with one thread per agent; the time bank is simulated per game, as on Kaggle, where it resets at each game of a best-of-three match.
