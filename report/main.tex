\begin{abstract}
The Kaggle \emph{PTCG AI Battle Challenge} asks for an agent that plays the Pok\'emon Trading Card Game, where cards are hidden, draws are random and the legal moves change at every turn. A first attempt trained a large transformer to copy the moves of top players and then refined it with reinforcement learning; it copied 63\% of expert moves but never rated above 650 on the ladder. A second attempt uses a small network to guide a tree search on the game's own simulator, so the agent looks ahead before each move. Measured over hundreds of games per comparison, search raises the score against a fixed set of opponents from 0.75 to 0.90 and the ladder rating to $\approx$770. A network head that guesses the opponent's hand predicts it better than card counting, but feeding its guesses to the search wins no more games.
\end{abstract}

% ------------------------------------------------------------------------------
\section{Introduction}
At every decision the agent receives the board, its own hand, a log of past events and the list of legal options (play, attach, evolve, attack, pick a target, pick $k$ of $n$ cards), and answers with the indices of the options it picks. Three things make this hard: the opponent's hand and both deck orders are hidden, draws and coin flips are random, and the set of options is different every time. Kaggle provides about 5k replays of high-rated games, a C++ simulator that can play a game forward from any state once the hidden cards are filled in, and a rated ladder; each agent has 2 CPUs and a 600\,s thinking budget per game.

The report follows the project in order: a first agent that learned only from data (\S\ref{sec:gen1}), why its results misled, and the second agent that plans with the simulator and was evaluated far more carefully (\S\ref{sec:gen2}). Code: \url{https://github.com/AntoCordeiro/ptcg-agent}.

\paragraph*{Related work.} The second agent follows AlphaGo/AlphaZero, where a network proposes moves and evaluates positions inside a PUCT tree search \cite{silver2016mastering,silver2018general}, and expert iteration, where the network is then trained to imitate the search \cite{anthony2017thinking}. For hidden information it uses determinization, i.e.\ searching sampled guesses of the hidden state \cite{long2010understanding,cowling2012information}.

\section{First attempt: learning to imitate}\label{sec:gen1}
The natural starting point was imitation. Every decision in the top $\approx$650 replays became a training example (state and chosen option), 75k in total. A transformer \cite{vaswani2017attention,vinyals2019grandmaster} (\emph{PTCGDualCrossNet}, $d{=}256$) reads one token per card in play or in hand and one token per legal option, described by 332 hand-crafted features, and scores each option; letting option tokens attend to card tokens is what lets it handle a different set of options at every turn. Training (behavioural cloning) pushed it to score the expert's choice highest.

To go beyond copying, three refinements followed: offline RL with IQL \cite{kostrikov2022offline}, which weights each copied move by how much it seemed to help win; online RL with PPO \cite{schulman2017proximal}, where the agent played against older versions of itself; and an average of the weights of these models (WiSE-FT \cite{wortsman2022robust}). When playing, the agent took the network's top option and used the simulator only to spot an immediately winning attack, avoid emptying its own deck and re-rank near-ties, at about 6\,ms per move.

The most useful step turned out to be a data fix: each replay observation had been paired with the previous action instead of the next one, and correcting this raised expert-move accuracy from 40.9\% to 63.3\%. The RL refinements added almost nothing (IQL 63.4\%). Worse, the local tests between versions, 20--40 games each, pointed the wrong way: a version that looked +240 Elo stronger scored 500 on the ladder against 650 for its predecessor, and over 350 local games the 650-rated version scores only 0.32. Two lessons shaped the second attempt: the agent used under 1\% of its thinking time while a perfect simulator sat unused, and tests need many more games and fixed opponents.

\section{Second attempt: a small network that guides search}\label{sec:gen2}
\paragraph*{Network.} The input keeps the card and option tokens but drops the hand-crafted features: each card token carries its identity and a few raw numbers (HP, damage, attached energy, zone, owner), and each option token is linked to the cards it acts on. Card effects need no hand-written description: the simulator plays them out during search. A 4-layer transformer ($d{=}192$, 2.6M parameters, fast on one CPU core) has four outputs: a score for each option (policy), the probability of winning (value), how many cards to pick in a $k$-of-$n$ choice (count), and which cards the opponent is holding (belief). The belief label comes for free, because replays store each player's own view, hand included. Training used 453k decisions from the top 3{,}000 replays, split 90/5/5 by game so that test positions come from unseen games. The value output first memorised the outcomes of the 3k training games, so it was retrained on 8k games the network played against itself, still imitating replays.

\paragraph*{Search.} Before each real decision with at least two options, the agent fills in the hidden cards with a plausible guess, a \emph{world}: its own deck order and prizes are shuffled from its unseen cards; the opponent's decklist is the one among 120 lists collected from replays that best matches the cards seen so far; the opponent's hand is drawn uniformly from the unseen cards or according to the belief output. The world is handed to the simulator and a Monte Carlo tree search explores moves for both players. The policy decides which moves are worth trying and the value scores positions, so games need not be played to the end. The most explored move is played; each decision gets a share of the remaining time bank. Finally, the network was trained to imitate the search's choices from self-play games (expert iteration), to point the search to better moves.

\paragraph*{Evaluation.} Offline metrics use held-out games. Every playing comparison uses 200--400 games on a fixed set of six opponents (two first-attempt agents and the network piloting four popular decks), the real time budget, 95\% Wilson intervals, and a sequential test (SPRT) to decide when a difference is real.

\paragraph*{What the network learned.} The policy picks the expert's move 70.0\% of the time (21.7\% at random) and the self-play value predicts outcomes better than a constant (Brier .226 vs .249, Tab.~\ref{tab:abl}). The deck that dominates top replays, Dragapult, scores only 0.49 with this network, Kangaskhan/Crustle 0.73 (240 games each); the agent plays Crustle.

\paragraph*{Search.} Looking ahead is where the strength comes from (Fig.~\ref{fig:scaling}): 0.75 without search, 0.87 with 256 simulations, 0.90 with the time-bank agent, and the search agent beats its own network 0.59 head to head. Two results about hidden information were unexpected. The belief output guesses the opponent's hand better than counting (AUROC .752 vs .711), yet worlds drawn from it win no more games (0.48). And four worlds lose to one world with the same total effort (0.39, $-75$ Elo): each of the four trees is a quarter as deep, and depth matters more than exact knowledge of the hand. Expert iteration helped once (+49 Elo for the search agent) and then stopped improving.

\section{Discussion and conclusions}
On the ladder the second agent rates 737--770 against 500--650 for the first (Tab.~\ref{tab:gen}), and the one local ranking that could be checked there (one world better than four) held (768 vs 737). Better imitation and RL did not make a better player; a smaller network guiding search on the real engine did. Limitations: four of the six test opponents share the agent's network and chose its deck, so the local score saturates at 0.90, while opponents rated 800+ remain hard (0.36--0.52).

\section{Statement on the use of AI}\label{sec:ai}
I used AI assistants throughout the project, in two phases.

\emph{First attempt (\S\ref{sec:gen1}).} My coding assistant was Gemini 3.8 Flash (Google). It wrote a large part of the code (replay parsing, feature extraction, the relational transformer, the BC/IQL/PPO training scripts, the light search and the deck tournament), and it helped me debug the pipeline and go through Kaggle replays of lost games.

\emph{Second attempt (\S\ref{sec:gen2}) and report.} I then moved to Claude Opus 5.5 (Anthropic), working as an agentic assistant. It reviewed the first system and helped me plan the restart, wrote most of the new code (parser, network, MCTS, evaluation harness, submission builder), ran training and evaluation jobs on my machine through a job queue, analysed logs and ladder episodes, made the figures and helped me draft and edit this report.

The goals and the main design decisions were mine: what to keep, what to drop, which agents to submit. I ran the Kaggle submissions, reviewed the code and checked every reported number against the logged outputs in the repository (\texttt{experiments/}, \texttt{RESULTS.md}). I understand the methods and the code, can explain them, and take full responsibility for the content of this report.
